## 5. Гейти якості (entry / exit)

**Entry (щоб реліз взагалі почали тестувати):**
- acceptance criteria сформульовані вимірно (число + одиниця + поріг). «Має бути швидко» повертається автору з точним формулюванням на заміну;
- названо всіх консюмерів зі зміненим контрактом (розділ 3).

**Exit (щоб реліз вийшов) — усі 6 обов'язкові:**
1. `npx tsc --noEmit` — exit 0;
2. `npx vitest run src` — 0 fail (сьогодні: 193/193);
3. killtest без куки — `failures: 0`;
4. killtest з кукою — `failures: 0`;
5. сценарій кожного консюмера з розділу 3, прогнаний ПІСЛЯ зміни;
6. для client-facing збірки: APK установлений на **реальному пристрої**,
   логін-шлях пройдений, скріншоти критичних екранів додані, SHA256 APK
   зафіксовано, жоден екран не містить неправдивого твердження.

CI покриває лише 1, 2 і `npm audit --omit=dev --audit-level=high`
(`F:\communal\.github\workflows\ci.yml`). **Гейти 3–6 сьогодні не
автоматизовані і виконуються вручну — це відомий розрив, не «покрито CI».**

## 9. Інваріанти продукту (порушення = BLOCKED)

- **INV-1 auth.** Кожен маршрут поза `PUBLIC_PATHS` (`F:\communal\src\proxy.ts:35`) вимагає валідної сесійної куки, перевірка — один раз на межі проксі.
- **INV-2 CORS.** `Access-Control-Allow-Origin` — рівно `https://localhost`, ніколи `*`, разом із `Access-Control-Allow-Credentials: true` (`F:\communal\src\lib\cors.ts`). Wildcard + куки взаємовиключні за специфікацією Fetch.
- **INV-3 правдивість підпису.** UI не має права твердити про дію, якої система не виконує. Інтеграції з EPS у коді НЕМАЄ (`epsConnected: false`, `F:\communal\src\lib\notifications.ts:253`; `submittedToEps: false` пишеться завжди, `F:\communal\src\app\submit\page.tsx:286`). Порушення зафіксовано сьогодні — D1 у тест-плані.
- **INV-4 гроші.** Жодне грошове чи фізичне число не показується як `NaN`, `Infinity`, від'ємне або округлене до нуля так, що порада втрачає сенс.
